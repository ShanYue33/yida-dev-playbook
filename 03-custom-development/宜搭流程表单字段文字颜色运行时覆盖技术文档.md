# 宜搭流程表单字段文字颜色运行时覆盖技术文档

## 1. 目的和结论

本文说明如何在宜搭流程表单中，将指定文本字段的输入文字和已提交后的展开详情文字显示为指定颜色。

宜搭标准 `TextField` 和 `TextareaField` 没有字段级“输入文字颜色”配置。本方案通过页面 JS 在运行时定位页面 DOM，并以 `color: ... !important` 覆盖默认样式实现。它只改变浏览器展示效果，不修改表单数据、审批结果或字段权限。

已验证的显示边界如下：

| 页面状态 | 是否可改色 | 原因 |
| --- | --- | --- |
| 流程发起或办理时的输入框 | 可以 | 表单字段已挂载，可定位 `input` 或 `textarea` |
| 已提交实例展开后的表单详情 | 可以 | 表单详情组件已挂载，可定位字段值展示节点 |
| 未展开的原生流程实例摘要 | 不保证 | 属于流程摘要组件，不是表单字段组件，表单页面 JS 通常未加载 |

## 2. 适用条件和风险

适用于流程表单中的单行文本和多行文本字段，需要在“页面 JS”的 `didMount` 生命周期中运行。

该方案依赖宜搭当前页面 DOM 结构，例如字段 ID、`.next-form-item`、`.next-form-item-label` 和 `.next-form-preview`。宜搭升级、切换页面形态、使用 iframe 打开表单或字段标题重名后，都可能需要重新验证。

不要把聊天或 Markdown 中的 ` ```javascript `、` ``` ` 粘贴进宜搭页面 JS 编辑器；它们不是 JavaScript 代码。

## 3. 实施前准备

1. 在表单设计器中选中目标字段，进入“高级”配置，复制字段唯一标识。常见格式为 `textField_xxx` 或 `textareaField_xxx`。
2. 记录字段实际标题。标题必须唯一；如果有同名字段，应调整标题，或针对实际 DOM 增加更精确的定位条件。
3. 在流程发起页和已提交实例的展开详情页分别用 F12 验证。不要使用其他表单的字段 ID。

## 4. 可复用代码

将以下代码放入流程表单“页面 JS”的 `didMount` 中。仅替换 `fieldId`、`fieldLabel` 和 `color` 三个变量。

```javascript
export function didMount() {
  (function () {
    // 目标字段唯一标识，例如 textareaField_xxx
    var fieldId = 'textareaField_xxx';

    // 目标字段标题，建议确保当前表单内唯一
    var fieldLabel = '业务说明';

    // CSS 颜色值，可替换为企业规范色
    var color = '#ff0000';

    function paintField() {
      // A. 流程发起或办理页：定位输入控件并改色
      var field = document.getElementById(fieldId);
      var input = field && (
        /^(INPUT|TEXTAREA)$/.test(field.tagName)
          ? field
          : field.querySelector('input, textarea')
      );

      if (input) {
        input.style.setProperty('color', color, 'important');
      }

      // B. 已提交实例展开后的详情页：按标题找到字段值并改色
      var items = document.querySelectorAll('.next-form-item');

      for (var i = 0; i < items.length; i++) {
        var labelNode = items[i].querySelector('.next-form-item-label');
        var label = (labelNode && (labelNode.innerText || labelNode.textContent) || '')
          .replace(/\s/g, '');

        if (label.indexOf(fieldLabel) > -1) {
          // 宜搭可能生成多个值展示层，全部设置以覆盖真正显示文字的节点
          var valueNodes = items[i].querySelectorAll('.next-form-preview');

          for (var j = 0; j < valueNodes.length; j++) {
            valueNodes[j].style.setProperty('color', color, 'important');
          }
        }
      }
    }

    // 首次渲染后立即执行
    paintField();

    // 应对流程展开、异步加载或切换审批节点后的 DOM 重绘
    var observer = new MutationObserver(paintField);
    observer.observe(document.body, {
      childList: true,
      subtree: true
    });

    // 限时监听，避免长期占用页面资源
    window.setTimeout(function () {
      observer.disconnect();
    }, 8000);
  })();
}
```

## 5. 代码工作原理

`didMount` 在表单组件挂载完成后执行。立即执行函数把变量限定在当前脚本内，避免污染页面全局变量。

填写状态下，代码优先以 `fieldId` 定位字段；字段节点本身可能就是输入控件，也可能只是外层容器，因此会继续向下查找 `input` 或 `textarea`。找到后使用 `setProperty` 写入带 `important` 的文字颜色，减少被宜搭默认样式覆盖的概率。

展开详情时，输入控件会被只读展示节点替代。代码遍历 `.next-form-item`，先读取 `.next-form-item-label` 中的字段标题，再在命中的字段范围内获取全部 `.next-form-preview`。全部设置颜色的原因是同一字段可能存在多个展示层；无需事先猜测哪一层最终承担文字显示。

`MutationObserver` 监听页面新增或替换节点。流程实例展开、审批节点切换和异步加载可能会重新创建 DOM，监听到变化后再次执行 `paintField`。监听器在 8 秒后主动关闭，平衡展示稳定性与页面性能。

## 6. 验收步骤

1. 保存页面 JS，重新打开流程发起页。
2. 在目标字段输入任意文字，确认输入文字为目标颜色。
3. 提交一条测试流程数据。
4. 打开该流程实例并展开表单详情，确认目标字段的已提交值为目标颜色。
5. 切换审批节点或刷新详情页后再次确认颜色仍生效。
6. 接受未展开原生流程摘要仍使用平台默认颜色；若摘要也必须定制颜色，需要单独建设自定义流程详情或任务列表页面。

## 7. 常见故障与排查

| 现象 | 常见原因 | 处理方式 |
| --- | --- | --- |
| 输入页不变色 | 字段 ID 错误，或代码不在表单自身页面 JS 中 | 重新从目标字段“高级”配置复制唯一标识；确认脚本写在当前表单 `didMount` |
| 展开详情仍是黑色 | 字段标题仍是占位文字、标题不一致或只选中了一个展示节点 | 使用真实 `fieldLabel`；保留 `querySelectorAll('.next-form-preview')` 的循环 |
| 手工在 F12 执行可变色，刷新后恢复黑色 | 手工代码未保存到页面 JS，或当前流程详情未加载表单组件 | 保存页面 JS；确认是在“展开后”的表单详情区域验证 |
| 未展开流程摘要为黑色 | 摘要区域不属于表单字段 DOM | 属于原生页面边界；如需定制，采用自定义流程详情或任务列表页面 |
| 自定义页面弹窗中不生效 | 表单位于 iframe，父页 `document` 无法选中表单节点 | 将代码写入表单自身页面 JS，或在 iframe `onLoad` 后向同源子文档注入 |
| 平台升级后失效 | CSS class 或 DOM 层级变化 | 按第 8 节重新执行 DOM 诊断并调整选择器 |

## 8. DOM 诊断命令

在已提交且已展开的流程详情页打开 F12 控制台，执行以下表达式。它返回字段数量、值展示节点数量和当前字段标题，便于核对选择器和标题。

```javascript
JSON.stringify({
  items: document.querySelectorAll('.next-form-item').length,
  previews: document.querySelectorAll('.next-form-preview').length,
  labels: Array.from(document.querySelectorAll('.next-form-item-label'))
    .map(function (e) { return (e.innerText || e.textContent).trim(); })
})
```

若返回结果显示多个 `.next-form-preview`，继续对全部节点设置颜色即可。若 `items` 或 `previews` 为 `0`，说明当前页面不是该表单详情 DOM，需要重新检查页面上下文、iframe 或新版组件结构。

## 9. 变更和维护建议

本方案属于前端展示增强，不应承载审批判断、数据校验、权限控制或风险提示的唯一依据。业务规则仍应通过字段校验、流程规则、字段权限和后端逻辑实现。

每次修改字段标题、迁移流程表单、切换 PC/移动端页面形态或宜搭版本升级后，应至少回归验证“填写页”和“展开详情页”两个场景。
